# DSH Retry Manager

为 DSH 增加模型级默认重试次数、当前对话覆盖和可取消的重试状态。

## 使用

- **设置 → 内置插件 → 请求重试**：全局默认可手动输入 0–100 次，按 Enter 或点 **保存全局默认** 生效；也可勾选“继承提供商设置”后保存。模型规则仍按“提供商 ID + 模型 ID”配置。
- **全局重试间隔**：取消“继承提供商重试间隔”，输入 0.1–3600 秒（精确到 0.1 秒）后保存。自定义值是固定本地间隔，不指数增加，统一作用于所有模型和对话；次数规则仍各自生效。
- **对话右上角 → 重试 N 次**：选择继承、关闭或当前对话自定义次数。
- 重试进行中可看到错误类型和进度；点击 **取消本次重试** 停止当前轮次，保留排队消息。

优先级：**当前对话 > 模型 > 全局 > 提供商**。0 为关闭，最多 100 次。
“3 次重试”指首次请求失败后最多再请求 3 次，不是整个对话共用 3 次。每个新模型步骤重置预算。

## 安装与卸载

需要 DSH **0.2.2-rc.5** 或兼容的后续 0.2.x 版本；本版已在 0.2.2-rc.5 验证。

本地工程安装：将本包加入目标 profile 的依赖，并在其 package.json 的
`dsh.profile.bundles` 中追加 `dsh-retry-manager`。启用 HMR 的宿主无需重启。

插件 bundle 会暂时禁用官方 `llm-retry` 条目，并由本插件调用**同一套官方执行器**。
不要手工重复插入本插件，也不要同时启用原来的执行器。
移除本 bundle 后，下层官方配置自动恢复；不要只在条目列表里停用插件，否则官方条目仍会受 bundle 禁用。

## 行为与边界

- 复用官方持久重试事件、退避和取消机制，不修改 DSH 核心或安装包。
- 默认重试超时、传输失败、服务端错误、限流与空响应；提供商自定义可恢复错误码仍可沿用。
- Responses 流内明确的 `Upstream service temporarily unavailable`、`Upstream request failed, please try again later`（包括 `server_error:` 前缀）即使被适配器归为 `PI_AI_ERROR`，也按 `SERVER` 继续重试；沿用同一失败步骤的预算与间隔，不重置计数。未知、认证、配额、配置、pending／deferred 等错误不会因此一概重试，原始失败文本保留。
- 手动停止、认证／配额／请求参数错误不重试；上下文溢出和图片卸载交由 DSH 的相应恢复机制。
- 不提供无限重试：上游 always 模式降为最多 5 次；上游 normal 上限超过 100 时限制为 100。
- 自定义间隔继续沿用官方 Retry-After 规则：适配器提供的有效值不超过配置间隔时会替代本地等待，超过该间隔则停止本次自动恢复；需要原提供商的完整退避策略时，勾选继承间隔。
- 旧配置文件缺少间隔字段时自动按继承处理，不改变已有次数与模型／对话覆盖。
- 配置通过界面保存后直接生效，无需重启 DSH 或重载插件；尚未进入恢复的步骤读取最新配置。当前步骤首次进入恢复后固定其策略，等待中修改次数或间隔不会重置该步骤预算或等待策略，下一个失败步骤生效。
- 只重试失败的模型步骤，不重新执行之前已完成的工具。失败部分输出不进入成功的模型历史。
- 网络恢复是重新请求当前步骤，不保证从上次最后一个字续写。每次重试可能产生费用。
- 直接调用 ctx.llm.stream() 的辅助消费者仍为单次调用；进程崩溃／系统休眠后的任务恢复不在本插件范围。
- 设置页使用 DSH 受认证、仅 owner 可用的 API；并发窗口的陈旧写入返回冲突，不覆盖新配置。
- 配置自动持久化到当前 profile 的 `retry-manager/state.json`；删除插件不会删除配置。
- 每个 profile 应只运行一个宿主实例；不要让多个进程同时编辑同一配置文件。

## 开发与验证

`npm install --legacy-peer-deps`

`npm run build`

`npm test`

真实 DSH agent 集成测试：将环境变量 `DSH_DIST` 指向 DSH 的 package.json 或 lib/bin.js，运行
`npm run test:integration`。找不到真实 DSH 会失败，不会以桩或跳过伪装通过。
可将 `DSH_TEST_ROOT` 指向统一临时目录。

在相同 `DSH_DIST` 环境下，`npm run test:responses` 使用构建后的插件、真实 DSH Responses 适配器和本地 HTTP 服务器，覆盖 502 → 流内临时上游错误 → 成功、统一预算、5 秒真实等待、取消、永久错误反例和工具不重放。运行前先 `npm run build`，不会调用付费模型。

本次还用隔离 Web profile、真实本地 HTTP 故障服务器和无头浏览器完成界面及 503、429、
断流、超时、空响应的验证；无付费模型请求、无鼠标移动或焦点抢占。

配置持久化依赖 write-file-atomic；输入验证依赖 Zod；重试执行器使用 DSH 自带的官方插件。
